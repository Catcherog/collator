# 数据清洗与数据飞轮 - Verification Checklist

## 模块结构与配置验证
- [ ] 目录结构符合 src/data-cleaning/{core,rules,schemas,utils,config} 规范
- [ ] 7张核心表的schema配置文件存在且JSON格式合法可解析
- [ ] 同义词库配置包含6种风格（日系清新、韩系唯美、复古胶片、暗调情绪、法式浪漫、国潮古风）的同义词
- [ ] 清洗规则配置文件结构清晰，包含格式规则、校验规则、评分权重
- [ ] 模块入口文件存在，能正确导出所有公共API

## 通用工具函数验证
- [ ] 手机号格式化函数：能正确去除横杠、空格、括号，输出11位纯数字
- [ ] 手机号校验：非11位数字时标记错误
- [ ] 日期解析："今天"、"明天"、"后天"能正确转换为YYYY-MM-DD格式
- [ ] 日期解析："这周六"、"下周末"等相对日期能正确计算（或标记待确认）
- [ ] 金额归一化："2000多"、"两三千"、"1k"能正确映射到标准区间
- [ ] 字符串标准化：能正确trim、全角转半角、去除多余空格
- [ ] 日志工具：支持info/warn/error级别，带时间戳输出

## 核心清洗引擎验证
- [ ] Pipeline架构支持串联多个清洗器按顺序执行
- [ ] 格式清洗器正确调用工具函数处理手机号、日期、金额
- [ ] 枚举映射清洗器能通过同义词匹配将非标准值映射到标准枚举
- [ ] "小清新" → "日系清新" 同义词映射正确，置信度标记合理
- [ ] 去重清洗器：基于手机号能识别重复客户数据
- [ ] 空值填充：可选字段缺失时能填充默认值或标记
- [ ] 所有自动修正都记录在corrections数组中（原值、新值、原因）
- [ ] 清洗过程中出现异常不抛出，降级为标记问题继续处理
- [ ] 单条数据清洗处理时间<10ms

## 业务规则校验器验证
- [ ] 必填字段缺失时返回failed状态，errors数组包含缺失字段列表
- [ ] 字段类型不匹配（如手机号传了非数字）能检测到
- [ ] 枚举值不在允许列表中时返回warning或failed
- [ ] 跨字段逻辑校验能检测矛盾（如拍摄日期早于咨询日期）
- [ ] 校验结果格式统一：包含status(passed/warning/failed)、errors[]、warnings[]
- [ ] 客户表校验：手机号必填且格式正确
- [ ] 项目表校验：项目状态在允许枚举范围内

## 数据质量评分验证
- [ ] 完整合法的数据（所有必填字段正确、枚举合法）质量分≥90分
- [ ] 包含手机号格式错误+非标准枚举值+1个可选字段缺失的数据得分在50-70区间
- [ ] 扣分明细能精确对应到具体字段和问题类型
- [ ] 质量等级划分正确：≥90优、70-89良、50-69中、<50差
- [ ] 每个质量问题都附带改进建议文本

## 操作日志验证
- [ ] 每次清洗修正操作都产生日志条目
- [ ] 日志条目包含：时间戳、操作类型、表名、记录标识、字段名、原值、新值、原因
- [ ] 日志以JSONL格式追加写入，不破坏历史记录
- [ ] 支持按记录ID查询该数据的所有历史修改
- [ ] 支持按表名和时间范围筛选日志

## 同义词自学习验证
- [ ] 提交用户修正（如"森系"→"日系清新"）后，同义词库能持久化保存
- [ ] 同一原始值被修正到同一目标值≥3次时，标记为"建议自动添加"
- [ ] 同义词库变更有版本记录，支持查看历史版本
- [ ] 更新同义词库后，下次处理相同原始值时能自动映射

## 数据质量扫描验证
- [ ] 能正确调用飞书API拉取指定表的数据，支持分页处理
- [ ] 存量数据扫描能检测出已入库数据中的格式问题（手机号带横杠/空格）
- [ ] 问题清单每条包含：记录ID、问题类型、问题字段、问题描述、建议修正值
- [ ] 扫描过程有进度日志输出，显示已处理/总数
- [ ] 扫描不修改数据，只生成问题报告

## 批量处理与质量报告验证
- [ ] 批量数据接口支持接收数组输入，逐条处理
- [ ] 批次统计正确：总条数、通过数、警告数、失败数、通过率百分比
- [ ] 问题分布统计：按字段统计错误次数，按问题类型聚合
- [ ] 批量处理遵循分批原则（内部处理≤200条/批）
- [ ] 生成的质量报告文本格式与现有批量导入预览风格一致
- [ ] 20条测试数据的批量处理能正确统计并输出报告

## 集成与兼容性验证
- [ ] 模块能通过Node.js require正确导入
- [ ] 示例脚本（单条清洗、批量清洗、质量扫描）可直接运行
- [ ] 新增测试表只需添加schema配置，无需修改核心代码
- [ ] 清洗输出格式符合data-parsing-templates.md定义的中间JSON结构
- [ ] 不破坏现有lark-cli工作流，可作为独立模块使用
- [ ] 所有代码文件放在src/data-cleaning/目录下，不散落其他位置

## 边界情况与容错验证
- [ ] 空输入、null、undefined等异常输入不崩溃
- [ ] 完全无法识别的数据返回failed状态和说明
- [ ] 同义词库配置文件损坏时能降级使用默认规则
- [ ] 飞书API调用失败时有错误处理，不导致进程退出
- [ ] 大批量数据（>500条）处理不内存溢出
