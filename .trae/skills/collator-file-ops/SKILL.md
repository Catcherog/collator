## 一、项目结构扫描

### 目的
快速了解项目当前文件分布，识别散落在错误位置的文件。

### 执行步骤

1. **扫描根目录**：列出 `collator/` 下的所有文件和一级子目录
2. **对比标准结构**：与 `项目总览.md` 中的目录结构对比
3. **标记异常文件**：找出不在标准位置的文件

### 标准目录清单

```
✅ 允许在根目录的：.gitignore, README.md, package.json, tsconfig.json 等构建配置
✅ .trae/      → AI配置
✅ docs/       → 文字文档
✅ src/        → 代码与配置
✅ public/     → 静态资源
❌ 其他任何文件/文件夹 → 需要整理
```

### 输出格式

```
📂 项目结构扫描结果：

✅ 正常文件（位置正确）：
   - .trae/skills/lark-shared/SKILL.md（飞书认证/权限基础）
   - docs/guides/agent-core-config.md
   ...

⚠️ 需要整理的文件（位置不对）：
   - 根目录/某个散落文件.md → 应移至 docs/
   - src/某张图片.png → 应移至 public/
```

## 二、文件分类判断

### 判断规则（严格按顺序）

```
文件扩展名判断：
    .md / .txt                              → docs/
    .js / .ts / .py / .ps1 / .sh / .json   → src/（配置文件进 src/config/）
    .png / .jpg / .svg / .gif / .mp4 / .ttf / .pdf / .webp → public/
    .yml / .yaml / .toml / .env             → 根目录或 .trae/（视用途）

文件名/内容判断（扩展名不足以判断时）：
    文件名含 "rule" / "规则"                → .trae/rules/
    文件名含 "skill" / "技能"               → .trae/skills/
    文件名含 "knowledge" / "知识"           → .trae/Knowledge/
    文件名含 "SOP" / "流程" / "sop"         → docs/sop/
    文件名含 "report" / "报告"              → docs/reports/
    文件名含 "guide" / "指南" / "config"    → docs/guides/
    文件名含 "batch" / "task" / "config" 且为.json → src/config/
```

### 判断流程

```
1. 看扩展名 → 确定大类（docs/src/public）
2. 看文件名关键词 → 确定子目录（guides/reports/sop 或 config/）
3. 看文件内容前50行 → 最终确认（如JSON配置 vs 普通JSON数据）
4. 不确定时 → 向用户确认
```

## 三、文件读取

### 读取优先级

当需要了解项目信息时，按以下优先级读取：

| 优先级 | 文件 | 何时读取 |
|--------|------|---------|
| P0 | `.trae/Knowledge/项目总览.md` | 每次新会话、需要了解项目全貌 |
| P0 | `.trae/Knowledge/业务场景.md` | 需要理解业务背景 |
| P1 | `.trae/Knowledge/文档集索引.md` | 需要查外部文档 |
| P1 | `.trae/rules/飞书操作规则.md` | 涉及飞书API操作 |
| P2 | `docs/guides/agent-core-config.md` | 需要Agent配置详情 |
| P2 | `docs/guides/business-rules-library.md` | 需要业务规则约束 |
| P2 | `docs/guides/data-parsing-templates.md` | 需要数据解析模板 |
| P3 | `docs/sop/模特招募SOP.md` | 涉及模特招募场景 |
| P3 | `src/config/*.json` | 需要批处理配置数据 |

### 读取策略

- **小文件（<200行）**：一次性全文读取
- **大文件（≥200行）**：先读前100行了解结构，再按需定位读取
- **JSON配置**：先读前50行了解结构，再按需搜索特定字段

## 四、文件移动

### 前置条件
- 已通过「文件分类判断」确定目标目录
- 目标目录已存在（不存在则先创建）

### 移动规则

1. **禁止覆盖**：目标位置已有同名文件时，先报告冲突，让用户决定
2. **保持文件名**：移动时不改文件名，除非用户要求
3. **记录操作**：每次移动后输出操作日志

### 执行步骤

```
① 确认源文件路径和目标目录
② 检查目标目录是否存在 → 不存在则创建
③ 检查目标位置是否有同名文件 → 有则报告冲突
④ 执行移动（使用文件系统操作）
⑤ 输出操作结果
```

### 输出格式

```
📦 文件移动完成：

   源路径: docs/某文件.md
   目标路径: docs/reports/某文件.md
   原因: 文件名含"report"，应归入报告类
   状态: ✅ 成功
```

## 五、文件创建

### 规则
- 新文件必须放在正确的目录（按「文件分类判断」规则）
- 创建前检查是否已有类似文件可复用
- 遵循项目命名规范（中文+英文混合，见名知意）

### 命名规范
- 知识文件：`中文描述.md`（如 `项目总览.md`）
- 规则文件：`中文描述.md`（如 `飞书操作规则.md`）
- 技能文件：`SKILL.md`（放在对应目录下）
- 配置文件：`英文描述.json`（如 `batch1.json`）
- 报告文件：`StepN_英文描述_Report.md`

## 六、批量整理

### 触发条件
用户说"整理项目"、"归档文件"、"清理目录"时触发。

### 执行流程

```
① 扫描全项目文件
② 对比标准结构，生成差异报告
③ 列出所有需要移动的文件及建议目标位置
④ 等待用户确认
⑤ 逐批执行移动
⑥ 输出整理摘要
```

### 输出格式

```
📊 项目整理完成：

   🔍 扫描文件总数: 42
   ✅ 位置正确: 35
   📦 已移动: 5
   ⚠️ 需手动处理: 2

   移动详情:
   - 根目录/xxx.md → docs/guides/xxx.md ✅
   - src/yyy.png → public/yyy.png ✅
   ...

   需手动处理:
   - 某文件（原因：目标位置有同名文件，请手动决定）
```
