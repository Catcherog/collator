## 1.2 标准命名规范

### 1.2.1 通用命名公式

```
{类型前缀}_{业务ID}_{日期YYYYMMDD}_{版本}.{扩展名}
```

| 组成部分 | 取值规范 | 说明 |
|---------|---------|------|
| **类型前缀** | 大写英文，见下表 | 标识数据类型，便于排序与检索 |
| **业务ID** | 客户ID / 订单号 / 模特ID / 拍摄主题编号 | 强关联核心表主键；无业务ID时用 `COMMON` |
| **日期** | YYYYMMDD（8位） | 文件创建或业务发生日期，非修改日期 |
| **版本** | v1/v2/v3... 或 draft/final | draft=草稿，final=定稿；定稿后不再用 draft |
| **扩展名** | 小写 | 统一小写，避免 .JPG/.jpg 混用 |

### 1.2.2 各类型前缀与命名示例

| 数据类型 | 类型前缀 | 业务ID来源 | 命名示例 |

### 1.2.3 命名约束

1. **禁止字符**：文件名不得包含 `/ \ : * ? " < > |` 及中文标点 `【】（）`；标题中的 `【P0 待补充】` 等占位标记必须在定稿前清除。
2. **分隔符**：组成部分之间用下划线 `_`，业务ID内部用连字符 `-`（如 `CUST-202601`）。
3. **中文使用**：业务ID中的拍摄主题、客户名等可保留中文（如 `28_夏合情思`），但前缀和日期必须为 ASCII。
4. **版本升级规则**：每次内容修订递增版本号；`draft` → `v1` → `v2`；定稿标记 `final` 后如再修改，需重新进入 `draft` 流程并升级版本号。
5. **Phase 1 问题对照**：当前云盘"空名称.docx"、"热点.docx"违反命名规范，需重命名为 `MEETING_运营热点_YYYYMMDD_v1.docx` 或归档删除。

# 二、映射规则设计（Task 4）

## 2.1 知识库目标分类体系

### 2.1.1 设计原则

基于 Phase 1 审视报告发现的 4 类问题（命名不规范、分类混乱、内容重复、僵尸节点），目标分类体系遵循：

1. **层级 ≤ 3 层**（根节点 → 分类节点 → 文档节点），保持当前最大层级=2 的优势。
2. **一级节点改为纯索引页**（仅放目录链接），解决"容器节点本身也有正文内容"的结构性问题。
3. **统一命名前缀**：一级节点用"零、一、二..."中文序号；二级节点用"01-02-..."数字前缀。
4. **话术库上移**：解决"01-全场景话术库知识库"被限制在"获客与转化"下的可见性问题。
5. **新增"业务知识库"分类**：归集价格体系、地区资源、术语表等散落的业务知识。
6. **补齐缺失 SOP**：新增订单管理 SOP、客户主表维护 SOP、异常处理 SOP。

## 2.2 云盘目标目录结构

### 2.2.1 设计原则

基于 Phase 1 统计报告发现的云盘现状（已重组为"项目文件/{泽怀影像, 知识, 写真业务, 电影业务}"），目标目录结构遵循：

1. **保留现有业务线划分**：写真/电影/通用三线并行，不推翻重建。
2. **按"业务场景 + 时间 + 数据类型"组织**：三层目录分别对应业务线、业务子类、数据类型。
3. **根目录清理**：将散落根目录的 11 个文件归入对应业务目录。
4. **填充空文件夹**：短视频/花絮文件夹建立子分类，明确上传规范。
5. **孤立文件归集**：9 个孤立文件按类型迁入"运营记录"或"通用知识"目录。

| **订单管理表** | order_id | order_id, customer_id | STRONG（合同/报价单/项目统计） | 合同、报价单、项目统计表、成品发布情况表 |
| **拍摄执行表** | 拍摄任务ID / shoot_theme | shoot_theme, shoot_date, order_id | STRONG（策划案/成品/花絮/短视频） / WEAK（资源表） | 策划案、成品照片、花絮视频、短视频、底片、场地/化妆/道具资源表 |
| **模特信息表** | model_id | model_id | STRONG（模特模卡/简历/模特资源表） | 模特模卡、模特简历、模特资源表、服化道资源list |
| **客户信息主表** | customer_id | customer_id | STRONG（客户相关作品/沟通） / WEAK（客户咨询记录） | 作品文件夹（含客户标识）、客户沟通记录、客户资源库 |
| **话术库** | 话术ID | business_scene=ACQ | STRONG（话术库节点） | 全场景话术库知识库节点 |
| **异常日志表** | 异常ID | integrity_status, related_table | WEAK（所有数据异常时记录） | 命名违规、关联缺失、完整性不足等异常 |

### 2.4.2 关联方式定义

| 关联方式 | 定义 | 触发条件 | 示例 |
|---------|------|---------|------|
| **STRONG（强关联）** | 数据直接依赖核心表记录存在，删除记录则数据失效 | 文件元数据包含对应核心表的主键字段且非空 | 合同↔订单管理表（order_id 非空） |
| **WEAK（弱关联）** | 数据与核心表有业务关联，但不依赖记录存在 | 文件元数据包含业务标识但无主键，或通过目录结构推断 | 资源表↔拍摄执行表（通过资源类型推断） |

### 2.4.3 collator Agent 自动识别关联流程

```
非结构化数据输入
   ↓
Step 1: 文件名解析
   ↓ 提取类型前缀 + 业务ID + 日期 + 版本
   ↓
Step 2: 业务ID类型判断
   ├─ customer_id (CUST*) → 候选关联：客户咨询表/客户信息主表
   ├─ order_id (ORD*) → 候选关联：订单管理表
   ├─ model_id (MD*) → 候选关联：模特信息表
   ├─ shoot_theme (数字_名称) → 候选关联：拍摄执行表
   └─ COMMON → 候选关联：异常日志表（WEAK）
   ↓
Step 3: 元数据补全
   ↓ 调用 lark-base 查询候选表，验证业务ID是否存在
   ↓
Step 4: 关联确认
   ├─ 业务ID存在 → STRONG 关联，写入 related_record_id
   ├─ 业务ID不存在但目录/标签匹配 → WEAK 关联，记录推断依据
   └─ 完全无匹配 → 标记 integrity_status=MISSING，写入异常日志表
   ↓
Step 5: 双向关联建立
   ↓ 在核心表记录中更新"云盘文件链接"字段（需先在7张表新增此字段）
   ↓ 在文件元数据JSON中记录 related_table + related_record_id
   ↓
Step 6: 输出关联摘要
   → "已建立 STRONG 关联：PHOTO_28_夏合情思_001 ↔ 拍摄执行表 recXXX"
```

### 2.4.4 核心表字段补全建议

为实现双向关联，建议在 7 张核心多维表中统一新增以下字段（若不存在）：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 云盘文件链接 | URL | 关联云盘文件的飞书链接（多选） |
| 知识库节点链接 | URL | 关联知识库节点的飞书链接（多选） |
| 文件数量 | 数字 | 关联文件总数（自动统计） |
| 最后更新时间 | 日期 | 关联文件最后修改时间 |

3. **失败处理**：转换失败的文件标记为 `CONVERT_FAILED`，写入异常日志表，不进入下游环节。

```

   ↓
Step 1: 存储路由判断（按 data_category + business_scene）
   ↓
Step 2: 主存储写入
   ├─ 知识库 → lark-wiki nodes create + lark-doc 写入正文
   ├─ 云盘 → lark-drive files upload（按 storage_path 创建/复用目录）

Step 3: 获取存储 token + URL
   ↓

   ↓ lark-base records update（在 related_table 的 related_record_id 记录中更新"云盘文件链接"字段）

### 3.4.4 存储约束

2. **重名处理**：同名文件加 `_序号` 后缀（如 `_001`、`_002`），不覆盖。
3. **分批写入**：多维表批量更新每批 ≤ 50 条，避免 API 限频。
4. **失败重试**：存储失败自动重试 3 次（间隔 2/4/8 秒），仍失败则写入异常日志表。

# 四、数据更新与维护机制（Task 6）

## 4.1 时效性校验机制

### 4.1.1 变更检测方式

### 4.1.2 24 小时内更新映射关系流程

```

   ↓

   ↓

## 4.2 准确性校验机制

### 4.2.1 周度校验（每周一 06:00 执行）

| 校验项 | 校验方法 | 通过标准 | 异常处理 |
|--------|---------|---------|---------|
| **孤立文件检测** | 扫描云盘+知识库，识别无业务关联的文件 | 孤立率 ≤ 5% | 标记 MISSING，通知云盘管理员 |
| **命名规范检查** | 正则匹配文件名是否符合 1.2 节规范 | 规范符合率 ≥ 95% | 标记 NEEDS_RENAME，通知所有者 |
| **空文件夹检测** | 扫描云盘空文件夹 | 空文件夹数 = 0 | 通知云盘管理员决定填充或删除 |
| **存储位置一致性** | 检查文件实际路径与元数据 storage_path 是否一致 | 一致率 = 100% | 标记 PATH_MISMATCH，自动更新元数据 |

### 4.2.2 月度校验（每月 1 日 02:00 执行）

| 校验项 | 校验方法 | 通过标准 | 异常处理 |
|--------|---------|---------|---------|
| **映射冲突检测（多对一）** | 检查同一文件关联多个核心表记录，或同一记录关联过多文件（>50） | 冲突数 = 0 | 标记 CONFLICT，通知数据校验员 |
| **元数据完整性检查** | 检查必备元数据字段是否完整（1.3 节矩阵） | 完整性 ≥ 95% | 标记 PARTIAL，触发 3.3 元数据提取补全 |
| **关联有效性验证** | 调用 lark-base 验证 related_record_id 是否存在 | 有效率 = 100% | 标记 INVALID_RELATION，删除无效关联 |
| **双向关联完整性** | 检查文件元数据有 related_record_id 时，核心表记录是否有"云盘文件链接" | 完整性 = 100% | 自动补全缺失方向 |
| **僵尸节点检测** | 知识库节点 90 天未更新且无关联 | 僵尸率 ≤ 5% | 通知知识库管理员归档或激活 |
| **存储容量统计** | 调用 drive metas batch_query 统计上传文件大小 | 无阈值，仅记录 | 输出容量趋势报告 |

## 4.4 异常处理流程

### 4.4.1 异常分级

| 级别 | 定义 | 处理时效 | 示例 |
